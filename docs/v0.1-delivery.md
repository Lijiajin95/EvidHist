## 1. 实际功能

「史料与引用工作台」闭环：录入中文材料 → 保存不可变文本版本 → 查看与查找原文 → 选取引文并由后端按持久版本校验位置与字句 → 保存论断与证据绑定（支持/反对/提及/证据不足）→ 并列查看多来源证据与分歧 → 刷新或重启后仍可回查。

- 材料管理：标题/来源说明/材料使用条件/初始文本（粘贴或 .txt 导入）；内容以 SHA-256 散列为身份存为不可变版本；同材料可加新版本，旧版本与旧引用永久可回查；重复提交按自然键幂等返回既有资源（201→200 + created:false）。
- 引用定位：在版本全文中选取片段，前端把 UTF-16 选区换算为 Unicode 码点区间，后端从数据库读取版本内容校验区间与字句（错误码 invalid_range/quote_mismatch/version_not_found）；增补平面字符（𠀀 等）按码点计数。既有 `/v1/quotes/locate` 保留为「显式文本工具」语义。
- 论断与证据：论断按语句自然幂等；证据绑定校验引文后存储（来源+版本+区间+关系+说明并列展示）；默认 review_status=unverified，界面明确标注「未核查」，不声称史实已证实；同文不同出处保持独立材料，不做独立性合并。
- 持久化：PostgreSQL + 事务性 SQL 迁移（schema_migrations 记账，重跑安全）；测试环境隔离库（55432，tmpfs）；演示环境持久卷（55433）。

本版本**不包含**：史料真实性判断、自动推理、知识图谱、大规模采集、真实模型评测（fixture 评分链路维持既有状态）。

## 2. 安装、迁移、初始化、启动

```bash
make setup             # uv sync（含变异/安全组）
make frontend-setup    # npm install（frontend/package-lock.json 锁定）
make db-up             # 测试库（可选，测试/开发用）
make demo-up           # 演示库（持久卷，127.0.0.1:55433）
make demo-migrate      # 应用 SQL 迁移（幂等，可重跑）
make demo-seed         # 演示数据（合成材料，见下）
make demo-run          # 后端 http://127.0.0.1:8000
make frontend-run      # 前端 http://127.0.0.1:5173（/v1、/health 代理到 8000）
```

停止：`make demo-down`（保留数据卷；彻底清除数据需 `docker volume rm evidhist-demo-data`）；前端 Ctrl+C。演示服务当前状态见第 6 节。

## 3. 接口与数据

（OpenAPI 全量见 `contracts/openapi.json`；前端类型由其生成并受漂移检查约束。）

- POST /v1/sources、GET /v1/sources?q=、GET /v1/sources/{id}、POST /v1/sources/{id}/versions
- GET /v1/versions/{id}、POST /v1/versions/{id}/locate（404：source_not_found / version_not_found / claim_not_found）
- POST /v1/claims、GET /v1/claims、GET /v1/claims/{id}、POST /v1/claims/{id}/evidence
- POST /v1/quotes/locate（工具语义：显式文本）
- 数据表：sources / text_versions（UNIQUE(source_id, content_sha256)）/ claims（UNIQUE(statement)）/ evidence（自然键 UNIQUE）；迁移文件 migrations/0001_init.sql。

## 5. 已知限制与“发现但不碰”

已知限制：
- 无分页（个人规模，列表一次性返回；后续按量增长再引入）。
- 论断 review_status 固定 unverified（未核查），本轮不提供人工核查流转。
- 前端 MSW 组件测试中的多行选区以区间断言覆盖（jsdom 无视觉换行）。
- messages.ts 有 1 个防御性分支未覆盖（未知 API code 兜底文案）。
- Stryker×vitest 5 的运行时变异不重跑缺陷 → 前端锁定 vitest 4.1（已在 development.md 记录）。
- 重复提交幂等采用查询后插入，个人单用户顺序重试场景足够。极端并发下：sources 无唯一约束、可能产生同自然键重复行；text_versions / claims / evidence 有唯一约束、并发冲突会产生未捕获的 IntegrityError（500）而非幂等 200。独立审阅已指出，按单用户产品接受并如实记录。

发现但不碰（范围外，留后续）：
- tests/system/test_running_service.py 的 live_service 46 有效行、三个 300+ 行文件为提示级结构警告（记录不拆）。
- pre-push 钩子的 fast-tests 未包含新集成层（按现有设计，集成由 make 目标触发）。
- README/架构文档的 v0.1 状态描述已由本轮提交更新；知识图谱/采集等设计章节继续作为目标而非现状存在。
