# EvidHist 五个产品方向：产品价值、技术价值与小规模验证

日期：**2026-10-10，Asia/Shanghai**。本文件用于帮助用户思考和取舍，**没有作出路线决定，也没有实施原型**。比较基线为 [项目目标与现状](../../README.md)，并沿用 [相关项目版图](related-project-landscape-2026-10-10.md) 和 [识典专项研究](shidian-guji-analysis-2026-10-10.md) 的证据边界。原创说明采用本项目 CC BY-NC-SA 4.0，引用资料保持原许可。

## 1. 先考虑什么

建议先重点思考 **1.稿件引文核查器** 和 **2.专题档案数据加工台**。前者围绕交稿前的一次明确检查交付，最直接使用 EvidHist 已有的材料版本与引文定位基础；后者围绕一批材料到可审核数据的交付，若能接触真实研究团队和数据，可以升为第一选择。

**3.研究证据案卷**适合长期研究积累，但需要证明用户愿意持续更新；**4.史料来源谱系分析**有较高方法研究价值，独立产品需求可能更窄；**5.历史实体与纪年校核**宜先按插件或批处理工具思考，独立产品是否成立要由真实使用证明。

以上是工程和产品判断，不是已证实的市场排名。五个方向都有现有工具或相邻产品，不能把“没有检索到某项功能”作为别人没做的证据。识典已经提供古籍研究助手和引用追溯，泛化的“古籍 + AI 问答 + 引用”不足以说明新的产品价值。

| 方向 | 用户买到或获得的结果（假设） | 主要技术价值（工程判断） | 首要验证问题 |
| --- | --- | --- | --- |
| 1 稿件引文核查器 | 交稿前发现可修订的误引、定位错误和证据不足 | 文本定位、对齐、支撑核查及未知处理 | 是否真实改正稿件，并节省净核查时间 |
| 2 专题档案数据加工台 | 一批可回查、可修订的结构化研究数据 | 布局/字段抽取、合并、规范化与来源链 | 是否愿意再交另一批材料，审核成本是否降低 |
| 3 研究证据案卷 | 研究问题的证据、反证和判断可以长期更新 | 版本审计、证据关系和变更影响 | 是否持续回用，而非只觉得界面新鲜 |
| 4 来源谱系分析 | 值得考据的新线索和候选依赖关系 | 模糊复用检测、版本归并与依赖推断 | 相比现有工具是否增加有用发现并省排查时间 |
| 5 实体与纪年校核 | 脏字段批量规范、保留歧义且可重放 | 规则、区间、语境消歧与确定性重放 | 现有工具之后是否还有重复、可复现的批量痛点 |

## 2. 怎样区分事实与判断

**事实**仅指官方文档明确描述的已有能力和许可，不表示本次实测了效果；每类只选最多两个一手出处。**产品假设**包括谁遇到问题、使用频率、能否接触、愿不愿付款和商业模式，均尚未访谈。**工程判断**是对算法、数据模型和可复用资产的分析，不把实现复杂度当作技术价值。

本次没有估算市场规模、收入、开发工期或转化率，没有联系用户、发送消息、购买服务或运行竞品。建议的小试验、人数和材料页数是探索范围，未执行，也不是统计保证。

### 产品价值的判断尺度

- 有明确的任务触发点，例如交稿、交数据、追踪研究判断或清洗一批字段。
- 用户当前确实承担重复成本，并能拿出现有材料、人工结果或处理记录。
- 输出导致真实修订、再次交付或持续使用，不能只看“觉得有意思”。
- 有愿意使用、提供下一批任务或付款的行为证据；口头赞同不等于已验证需求。

### 技术价值的判断尺度

- 关键结果可检查，可定位失败，能够与独立人工依据或已知规则比较。
- 可以积累有用资产：算法、规则、来源映射、错误样例、任务基准和用户修订依据。
- 同类后续任务能够复用，而不是每次重新定制全部逻辑。
- 维护和部署成本与用户得到的结果相称；大型图谱和多 Agent 数量本身不加分。

## 3. 方向一：中文历史稿件引文核查器

**产品定义：** 作者或编辑提供一篇中文历史稿件及已有合法参考文献，系统交付逐论断核查报告，让用户知道哪些引用可定位、哪些原文不支持表述、哪些数字/人名/日期需要修订，以及哪些仍无法核查。

| 项目 | 设想与边界 |
| --- | --- |
| 角色与触发 | 历史研究者、文史作者、编辑，在交稿、审稿或发布前检查出处；这是待访谈的用户假设。 |
| 输入 | 稿件、参考文献、底本或整理版本信息；先使用用户已有材料，不能默认能获取所有付费库原文。 |
| 交付物 | 论断—来源—原文位置—支撑关系表，误引/定位错/信息错配、证据不足及可修订事项，附人工复核状态。 |
| 可能商业形式 | 按次核查或团队工作流；只是候选，未证明愿付费或合理价格。 |
| 产品价值 | 把模糊的“提高可靠性”变成一篇稿件实际改正了什么，减少可避免的交稿错误。 |

**已有竞争事实：** scite 的 2021-02-12 官方教程已有稿件 PDF 引用分析，查看引用片段、撤稿/更正和支持/反对；匹配受 DOI、参考文献及 PDF 格式影响。Isonomia 当前宣称支撑核查、共同根源及漂移追踪，标为早期平台。[scite（当时口径）](https://scite.ai/blog/how-do-i-use-the-scite-reference-check)、[Isonomia](https://www.isonomia.app/)。**判断：** 中文历史材料、用户自带资料、具体版本定位和真实修订流程是否足以区别，需对照证明；不从旧文或早期状态推断对方当前不能做。

**技术资产判断与范围：** 文本对齐、OCR 位置映射、引用解析、数值/人名/日期错配、支撑核查、未知处理与人工复核可形成可验证资产。现有材料、版本和引文定位可用，整稿解析/语义核查仍需开发。先做精确引文和信息错配；没有原文就记未核查，不能从个别正确推出整稿正确。

**最小验证与风险（未执行）：** 找 3–5 位作者/编辑提供几篇稿件，先半人工交付，记录真实修订、误报及净核查时间。若复核警报抵消收益，停止扩展。源文取得、误报和专家信任是瓶颈；模型能解释文字不等于编辑愿意依赖它。

## 4. 方向二：专题档案数据加工台

**产品定义：** 限定一种材料，把地方志任官表、名册、民国统计表等一小批材料加工为每个字段均能回到卷页或原文位置的数据集，而不是建设通用 OCR 平台。

| 项目 | 设想与边界 |
| --- | --- |
| 角色与触发 | 研究团队、地方史机构或资料项目需要建表和交数据；角色与预算尚未验证。 |
| 输入 | 单一材料类型的 30–50 页或一小批文本，先约定字段及人工验收依据。 |
| 交付物 | CSV/JSON、逐字段来源位置、缺失/冲突标记、修订记录及必要的数据说明。 |
| 可能商业形式 | 按项目交付或部署；先验证服务，再判断共同部分能否产品化。 |
| 产品价值 | 减少人工录表，而且审阅者能解释和纠正每个字段，不只得到一张看似完整的表。 |

**已有竞争事实：** Transkribus 有历史文献表格/字段/实体抽取，CSV/XML/TEI、图像坐标和 API；MARKUS 有中文人地名/时间/官职标注及数据导出，代码 AGPL-3.0-or-later。[Transkribus](https://www.transkribus.org/document-data-extraction)、[MARKUS](https://github.com/dHumanities/markus)。**判断：** 仅识别成表并非区别；字段语义、跨页续表、规范化和可审核交付是否更好，需与用户现有方法比较。

**技术资产判断与范围：** 字段/布局、跨页合并、别名和纪年规范、质检及来源链可复用；已有存储可回查，抽取仍需新增。只选一类材料，明确必填/可缺失字段，保留原始/规范值，不把缺失补成确定值；不默认已获商业接口或资料授权。

**最小验证与风险（未执行）：** 与客户人工结果对照，计入修订/审核时间，看是否再次交同类材料。若全流程反复定制而不复用，保持项目服务；材料变化、验收责任和用户接触是风险。有真实机构及重复任务时可以升为第一。

## 5. 方向三：长期研究证据案卷

**产品定义：** 围绕一个研究问题长期保存论断、证据、反证、冲突、未知与人工修订，交付可复核且能持续更新的案卷。

| 项目 | 设想与边界 |
| --- | --- |
| 角色与触发 | 正在长期研究的个人或小团队，需要解释“我为何得出这个判断”；需求和付费均待验证。 |
| 输入 | 用户已有笔记和材料，尽量保留现有工作方式，避免要求先重录全部资料。 |
| 交付物 | 研究问题的论断/证据案卷，反证和未决问题、修订及更新说明，可导出回查。 |
| 可能商业形式 | 个人持续使用或团队协作；是否值得独立订阅未知，也可能仅适合自用。 |
| 产品价值 | 新证据出现时能追踪哪些判断需要重审，协作者知道哪些部分尚未完成。 |

**已有竞争事实：** Zotero 注释笔记保留引文和 PDF 页回跳；ResearchSpace 有来源片段、CRMInf 信念/论证以及作者/时间归属与不同视角。[Zotero](https://www.zotero.org/support/pdf_reader)、[ResearchSpace](https://researchspace.org/semantic-tools/)。**判断：** 笔记、回跳和论证图都有替代，要证明修订/冲突/变更影响更有用，不能重造普通笔记。

**技术资产判断与范围：** 论断关系、版本审计、变更影响、人工判定和导出可复用；已有绑定可用，完整案卷/导入/协作未完成。只围绕一个问题，读取现有笔记、保留争议未知；接受一个视图不等于愿维护第二套知识库。

**最小验证与风险（未执行）：** 与少量研究用户整理约 20 条现有证据，观察是否自发更新。只看图不回用则价值不足；迁移成本、笔记习惯及研究节奏是主要风险，应先有长期行为证据。

## 6. 方向四：史料来源谱系与文本复用分析

**产品定义：** 对同一事件或主题的一组文本提出复用、可能转引或共同出处的候选，展示对齐片段、时序/版本依据及人工确认/未知状态。

| 项目 | 设想与边界 |
| --- | --- |
| 角色与触发 | 考据研究者或专题研究项目需要排查材料相互依赖；独立产品需求可能较窄，尚未访谈。 |
| 输入 | 小范围有出处与版本信息的专题语料，最好存在专家已知判断作为对照。 |
| 交付物 | 重合片段、候选转引/共祖关系、出处与时间依据、人工确认和无法判断的关系。 |
| 可能商业形式 | 研究工具、项目合作或方法服务；用户频次及付费未知。 |
| 产品价值 | 避免将大量转抄当成多份独立证据，并找到值得继续考据的线索。 |

**已有竞争事实：** Passim 提供片段对齐、字符偏移/可用时的图像与引用位置及 seriatim 候选图，MIT；CollateX 提供版本对齐、差异/移位与校勘支持，GPL-3.0。[Passim](https://github.com/dasmiq/passim)、[CollateX](https://github.com/interedition/collatex)。**判断：** 相似工具已有，区别需来自中文变体、版本与依赖判定；相同文字/较早时间不能自动证明转引方向。

**技术资产判断与范围：** 模糊复用、版本归并、图约束和专家样例有较高研究价值，多数算法尚未实现，也未证明商业壁垒。先交付候选，区分已确认和未知，不能由相似阈值生成确定谱系或真值裁决。

**最小验证与风险（未执行）：** 对照专家已知小语料，看是否新增有用线索并省排查时间；只有已知相似则不扩平台。专家/语料难得、用户可能少，适合方法研究和专家合作；第三方许可须分别核对，不默认并入 MIT。

## 7. 方向五：历史实体与纪年批量校核工具

**产品定义：** 从混杂原文识别一批纪年或实体，登记依据、保留歧义并纳入人工复核/数据集流程，输出候选标识、时间区间和原文映射；初期只选纪年一类。

| 项目 | 设想与边界 |
| --- | --- |
| 角色与触发 | 研究数据库团队、数据加工人员或开发者，清洗一批历史字段；独立产品需求待验证。 |
| 输入 | 真实脏字段与上下文、原文位置和必要的朝代/版本依据。 |
| 交付物 | 原始值、候选规范值/ID或时间区间、理由、歧义和待人工核对清单，可重放结果。 |
| 可能商业形式 | 插件、离线批处理或集成组件；独立平台/付费模式尚未证明。 |
| 产品价值 | 减少批量重复查表和修改，让规范化中的假设可解释而且不丢失原始值。 |

**已有竞争事实：** 中研院已有最多 1,000 项批次中西历转换、年号/干支及改历选项，缺月日会按首日等转换；CHGIS V6 有历史行政时序数据，限免费学术研究、禁商业/转售/再分发。[中研院](https://sinocal.sinica.edu.tw/)、[CHGIS V6](https://chgis.fas.harvard.edu/data/chgis/v6/)。**判断：** 批量换算不能作为区别；混杂原文识别、歧义复核和工作流集成的剩余价值待核，查询缺省日期须与原文确定日期分开。

**技术资产判断与范围：** 语境、历法/区间、冲突约束、规则版本和确定性重放可以测试，但大多要新增，v0.1未具备这些能力。保留原始值和转换约定，缺日/重名给候选、区间或未知，不同时全建库，也不默认获得商业接口/数据权利。

**最小验证与风险（未执行）：** 对一批真实脏字段测出现有工具之后的余量和修订成本，只有重复痛点才继续。上下文缺失、免费替代及底层许可可能阻碍独立产品；宜先工具/插件，CHGIS商业使用和中研院API权限不能默认成立。

## 8. 与当前代码的距离和建议顺序

| 方向 | 当前可复用基础 | 主要新增工作 | 建议如何决策 |
| --- | --- | --- | --- |
| 1 | 材料、不可变版本、引文定位、论断证据 | 整稿引用解析、精确错配及支撑核查流程 | 默认优先验证，先证明真实修订与净收益 |
| 2 | 来源/版本存储与引文回查 | 一种材料的字段/布局抽取和数据验收 | 有真实客户/机构和重复资料时可升为第一 |
| 3 | 论断和证据绑定 | 笔记导入、案卷更新、证据变更影响 | 先有长期回用证据再做协作平台 |
| 4 | 资料、版本和来源记录 | 大量新增对齐/依赖算法、专家样例 | 专家合作与技术研究兴趣强时考虑 |
| 5 | 来源和原文映射 | 规则、历法、实体消歧及批次复核 | 先插件/组件，不从重平台开始 |

这是对当前 README 所描述实现范围的工程判断。v0.1 仍没有完整自动互证、知识图谱和真实模型质量评测；任何方向都需要新的任务验收，不以现有仓库测试通过证明已经达到产品目标。

对选择最有帮助的不是给五个方向主观打一个总分，而是确认：**你现在能接触谁的真实任务，能取得哪类合法材料，对方当前怎么处理，做完后会改变什么行为。** 如果没有用户入口，也可以为自身明确任务做工具，但应区分个人使用价值与商业需求证据。

本报告没有选定路线。下一步可以只挑一个方向完成上述小试验；其结果应决定继续、收窄、保留自用还是停止，而不是先承诺一个大型历史平台。
