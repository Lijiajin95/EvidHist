**本次实际执行**：编写并运行了本地采集器 `crawler/collect_ming.py` 等（`crawler/` 按项目约定不纳入版本库），从中文维基文库取得 730 页明代史料 wikitext 原文、对应的维基文库简体/繁體视图与正文/注分层段落，并逐条登记来源、版本、许可快照与允许用途。**未做**：跨来源互校、版本比对、OCR、入库。

## 1. 采集范围与口径

范围：维基文库**明代史部可得卷页**（11 部作品）。用户确认的口径是「文库可得全集」。

「完整」在此只能有一种诚实含义：**对文库实际可得的卷页穷尽抓取，并把不存在的卷页逐条登记为来源缺口**。维基文库对明代史料远不完整，不能把「文库没有」写成「已抓全」。

核验器把两个问题分开回答：

| 口径 | 含义 |
| --- | --- |
| 采集是否完成（`complete`） | 每个已发现的页面要么已取得且散列一致，要么已确认为来源缺口；没有 pending；且都有简繁视图与分层 |
| 来源覆盖率（`coverage`） | 已取得页数 ÷ **文库可获取基线**，与来源缺口一并如实列出 |

**覆盖率口径**：采集覆盖率 = 已得 ÷（已得 + 失败 + 未抓），衡量我们的采集是否把文库有的都拿到了；

## 3. 采集过程中发现的问题（均已实测）

### 3.1 《明實錄》各朝卷页标题前缀不统一

实测同一部书内混用五种前缀：`大明太祖高皇帝實錄/卷001`、`大明文皇帝實錄/卷001`、`成祖文皇帝實錄/卷011`、`明實錄/成祖文皇帝實錄/卷023`、`光宗貞皇帝實錄/卷一`；《大明純皇帝實錄》的目录还写成简体「大明**纯**皇帝實錄」。

只按首页前缀发现会**整批漏卷**。采集器因此按作品登记接受规则，并按页内实际链接递归发现。

### 3.2 悬空链接会伪装成缺卷（实际避免了漏两卷）

《明史/卷157》的页头写成：

```
| previous =  [[../卷 156 |卷 一百五十六 ]]
| next     = [[../卷 158 |卷 一百五十八 ]]
```

链接目标里多一个空格，指向 **不存在**的 `明史/卷 156`；而 `明史/卷156`（21 KB）与 `明史/卷158`（25 KB）另有正文且已由目录正确链接。

处理：404 后回退到去空白的标题，取回正文并登记 `kind=alias`。这类记录在汇总与核验中单列为**悬空链接**（`dangling`），不计入缺卷。若只按字面登记缺口，报告会显示「明史缺 2 卷」——**实际一卷不缺**。

### 3.3 《皇明經世文編》为空壳

首页仅 123 字节、`{{wwc}}` 加页头模板，**无任何卷页链接**，文库实际可得为 0。

### 3.4 校对标记 ≠ 空壳

《大明律》首页 81 KB、《大明會典》首页 36 KB 仍带 `{{wwc}}`。采集器把「带 `{{wwc}}`/`{{未完成}}` 维护标记」（`unfinished_marker`）与「几乎无正文的空壳」（`placeholder`）分开登记，避免把有大段正文的首页误报为空壳。

### 3.5 间歇性连接失败（原文阶段）

首次全量采集有 9 条 `status=error`，全部集中在《大明會典》连续卷次（卷一百六十一至一百六十七、卷二百二十七至二百二十八），均为重试 4 次仍失败（站点分块响应被截断 / SSL 中断）。幂等重跑后 9 条**全部取回**，最终错误数 0。

### 3.10 《皇明從信錄》：raw 没有正文，正文在渲染视图里（**引用规则例外**）

实测（2026-10-13）：《皇明從信錄》40 卷的 wikitext **全部**只有一条转写指令：

```
{{Header2|title=[[../]]|section=卷一|next=[[../卷02|卷二]]|from=四庫禁燬書叢刊}}
<pages index="四庫禁燬書叢刊 史部 第01冊.pdf" from=13 to=27 fromsection="" tosection=""/>
```

40 个文件各约 250 字节，剥离模板后**一个正文字符都没有**。正文由 `<pages>` 标签在**渲染时**
从 Page: 命名空间取回——卷01 渲染出 44 KB HTML、分层得到 614 段、约 1.7 万字。

**对本项目"引用一律用 raw 不转换原文"规则的例外**：该书只能引用 `view-*/` 与 `segments-*/`，
`raw/` 不可当正文使用。核验器已把这类页面单列为 `transclusion_stubs` 并在报告中明确提示。

（同类页面在本次 34 部作品中仅《皇明從信錄》一处，40 页。）

### 3.9 并发写入撞车（操作失误，已纠正）

扩范围期间，先用 `nohup ... &` 启动了一个视图进程，随后又用受管后台任务启动了第二个。
两条进程**并发**请求同一站点（合计约 1.3 请求/秒），并同时写同一个 `.part` 临时文件，
导致受管任务在 `os.replace` 处崩溃（`FileNotFoundError`）。

处理：终止游离进程，恢复为**单进程**串行执行（实测约 25 页/分钟，与双进程的约 50 页/分钟可区分，
据此确认并发已消除），幂等续跑补齐。核对结果：0 残留 `.part` 文件、3136 行分层全部可解析、0 坏行。

**教训**：本项目对外的礼貌承诺是「单进程单线程」，启动方式必须统一走受管后台任务；
用 shell 后台符启动会失去进程跟踪，进而破坏这一承诺。

### 3.6 单页失败曾打断整轮视图抓取（已修）

视图阶段第一次运行时，`明史/卷62` 的繁體渲染请求重试 4 次仍失败，异常一路抛到 `main`，**整轮约 1500 个请求中止在第 395 页**（退出码 2）。

原因：单页容错只加在了原文采集器上，视图采集器沿用旧行为（任何请求异常都中止整轮）。已改为与原文一致——重试后仍失败的单页记 `status=error` 并继续，只有站点明确要求停止（401/403/429）才中止整轮。修复后带回归测试续跑，幂等跳过已完成的 395 页。

### 3.7 目录链接不等于全部内容：《南疆繹史》浅遍历会漏 57 页

《南疆繹史》首页只链到 `南疆繹史/勘本` **一页**；`勘本/卷01`–`勘本/卷30` 要再走一层才出现。
按首页直接子页统计只能看到 15 页，实际文库有 **73 页**——浅遍历会静默漏掉 57 页。

同类结构还有《石匱書》：其卷页靠 prev/next 相互指向，且简繁两套标题前缀各自成链
（`石匮書/卷五` 与 `石匱書/卷一` 并存），从卷五走到卷十六要十几层。

**结论：深度上限不能当作采集边界**。真正的边界是各作品的接受规则加 `visited` 去重（环由 visited 终止），
深度只是防跑飞的安全阀。默认从 3 层提到 25 层后，《石匱書》多取回 5 页、《南疆繹史》多取回 57 页。
截断本身也不再是静默的：被截断的页面会登记为 `status=pending`，核验据此判「采集未完成」。

### 3.8 同名异体字与简繁混用

- 《罪惟錄》页实为 `#REDIRECT[[罪惟録]]`（錄/録 异体字），按正文页标题登记。
- 《石匱書》标题简繁混用，接受规则须同时匹配 `石匮書/` 与 `石匱書/`。
- 《明實錄》各朝前缀混用五种（见 3.1），《大明純皇帝實錄》目录作简体「大明纯皇帝實錄」。

## 4. 不影响对方系统的措施（实测）

| 措施 | 实现 | 实测证据 |
| --- | --- | --- |
| robots fail-closed | 取不到 robots、或 robots 禁止目标路径 → 立即中止，不采集任何材料 | 单元测试；实跑 robots 快照存 `data-ming/robots/` |
| 仅用允许路径 | 只走 `/wiki/<页面>`（`?action=raw` 与 `?action=render&variant=`）；**不使用 `/w/api.php`**（robots 禁止） | 全程无 API 请求 |
| 串行 + 最小间隔 | **单进程单线程**，实跑 `--delay 1.5` | 原文 1.72 秒/条；视图 14–31 页/分钟；全程约 0.4 请求/秒 |
| 不并发 | 一次只跑一个采集进程；扩展范围时分批串行执行，不并行加压 | 本次扩范围时先让短的原文任务结束，再继续视图任务 |
| 描述性 UA | `EvidHistCrawler/0.1 (personal research project; contact: 592260959@qq.com)` | 每次请求均带 |
| 退避与服从指示 | 429/5xx 指数退避、`Retry-After` 优先；404 不重试 | 9 条错误按退避重试 4 次后放弃并登记 |
| **站点要求停止即停** | 401/403/429（含重试耗尽）→ 立即中止整轮并返回退出码 2，不再以 1 秒/页走完剩余上千页 | 单元测试；本次全程未触发 |
| 幂等与续跑 | 已有台账且文件在 → 不发请求；中断后重跑只补缺口 | 重跑仅 2 个前置请求 + 11 个待补页，耗时 5 分钟 |
| 不伪装内容 | 要求 `200 + text/x-wiki`；404 与错误页绝不落盘为正文 | `grep -rl "Wikimedia Error\|<html" data-ming/raw` 为 0 |
| 缺口即证据 | 目录里不存在的卷页写 `status=missing`（含 HTTP 404），是完整性证据而非失败 | 1017 条缺口记录 |

规模对照：Wikimedia 的 robots.txt 本身就是「有大量行为不端的爬虫、请负责任地访问」的提示；本次全程约 3250 个请求，分散在约 2 小时内，平均约 0.45 请求/秒，低于常见机器人 1 请求/秒的惯例。

## 5. 产物位置与可回查信息

每份材料登记：来源、URL、`Last-Modified`、内容 sha256、许可证快照及其散列、获取时间（UTC）、允许用途、所属作品、是否空壳、悬空链接指向、缺口原因。

缺口清单可回查：`verify_ming.py --list-gaps`，或读 `reports-ming.json` 的 `missing_titles`。

## 6. 许可与用途

维基文库站点文字按 **CC BY-SA 4.0** 提供，古籍原文本身属公有领域；每次运行先固定 `robots.txt` 与 `Wikisource:版权信息` 快照散列，取不到即中止（fail-closed）。

台账 `allowed_uses` 逐项标注：存储、内部检索、内部分析、公开展示、再分发为 `true`（再分发须署名并以相同方式共享）；**模型训练显式记为 `null`（未确认）**。

**注意**：本次保存的是文库转录文本，含文库贡献者添加的标点、分段与校对成果，不自动等于可靠校对本；引用、校勘与字形比对应回到 `raw/` 不转换原文，并注意转录与校对状态（`{{Textquality}}`、`{{wwc}}` 逐页不同）。
