# 明代多格式史料语料与文本/向量双检索原型（2026-10-19）

日期：2026-10-19（Asia/Shanghai）。状态：**本地工作区已跑通，未接入 EvidHist 产品代码、API 或数据库**。本文记录一次资料采集与检索原型的实际执行结果，不改变[首版最小技术方案](../minimal-technical-plan-2026-10-18.md)的范围（该方案第 2 节明确不做向量检索）；向量索引属于本地研究基础设施，不是产品实现。原创说明采用项目 [CC BY-NC-SA 4.0](../../LICENSE-DOCS.md)；第三方史料保留各自许可。

## 1. 本次做了什么

用户要求继续搜集明代资料，覆盖 wiki、txt、docx、pdf 等不同格式与结构化/非结构化材料，并同时支持文本检索与 RAG 检索。本次实际完成：

- 从**中文维基文库**取得《明史》332 卷、《明史紀事本末》81 页（含序）、《明通鑑》101 页，共 **514 页**、18,436,472 字节；
- 从**殆知阁**（GitHub 文本集）取得 **42 部**明代文献，含《明實錄》13 朝、《國朝獻徵錄》《皇明經世文編》《大明會典》《明會要》《明儒學案》《明一統志》《萬曆野獲編》等，原始 112.0 MB；
- 从 **archive.org 备份的中国国家图书馆扫描件**取得《明史》第 18 冊 PDF（71 页，17.5 MB，无文字层），用 macOS Vision OCR 得到 31,141 字；
- 实现并测试了 **DOCX** 段落/表格抽取，但**没有找到可合法使用的真实明代 DOCX 资料**，仅以一段维基文库文本生成夹具验证解析器，未计入语料；
- 将全部材料统一为 **557 条记录、80,887 个分块、43,782,665 字**，每个分块保留作品、卷次、来源、许可、原始文件散列与字符区间；
- 建立**文本索引**（SQLite FTS5，二元组 + 单字降权 + 繁简归一）与**向量索引**（BGE-small-zh-v1.5，512 维，80,887 条），并提供词法、向量、RRF 混合三种检索与带引文定位的 RAG 上下文构建；
- 用 **16 条明代查询**做卷级召回评测：词法 recall@10 = **1.000**、MRR = 0.437；向量 recall@10 = **0.688**、MRR = 0.458；RRF 混合 recall@10 = 0.938、MRR = 0.416。

**一个必须先说明的现状**：本机只有代码库，2026-10-12 与 2026-10-18 会话产生的 `crawler/` 数据（`data-ming/`、`data-ocr/`、`data-kanripo/`）不在这台机器上。本次是从零重建的**独立批次**，没有与旧批次做散列或版本比对；本文所有“已取得”只指本次实际落盘的文件。

## 5. 索引与检索

### 5.1 文本检索（FTS5）

- 表：`data/index/fts.sqlite`，576.3 MB；`chunks` 存原文与元数据，`chunks_fts` 为 contentless FTS5，两列：`bigrams` 与 `unigrams`。
- 归一：`zhconv` 繁转简后切片；二元组为主，单字列以 `bm25(..., 1.0, 0.2)` 降权。加单字列是为了解决古典传记“首见全名、此后只称名”的问题（《明史》卷 170 首段“于謙”，下文多作“謙”；只索引二元组时“于谦”查不到该卷）。
- 查询：先按空格/标点/停用字切段，**段间 AND、段内 OR**，不足时用全体 OR 补齐；这样“于谦在北京保卫战中做了什么”会要求“于谦”与“北京保卫战”两类词同时出现，而不是把“了什/什么/中做”当检索词。
- 实测：“于谦”前五为《明史紀事本末》卷 35、《明通鑑》卷 30/31、《明史》卷 170（第 5）；“土木之变 英宗 亲征 王振”前二为《明史紀事本末》卷 29（王振用事）、卷 32（土木之變）。

### 5.2 向量检索

- 模型：`BAAI/bge-small-zh-v1.5`（512 维），查询侧加官方中文检索指令，文档侧不加；MPS 加速。
- 规模：80,887 × 512，float32，158 MB；599 秒，135.1 块/秒；顺序散列 `67d9ed72…` 与 `chunks.jsonl` 对齐。
- 用法：`search.py --mode vector` 或 `rag_prompt.py` 在词法结果不足 3 条时回退。

### 5.3 混合检索（RRF）

- `search.py --mode hybrid`：词法与向量各取前 30，按 `1/(60+rank)` 融合，取前 k。
- 在本批评测上 RRF **没有超过词法**（见 §6），原因是向量 top 结果常偏离卷级预期，融合会把词法命中挤出前十。保留该模式用于探索，不作为默认。

### 5.4 RAG 上下文

`scripts/rag_prompt.py` 不调用大模型（本机没有可用 API Key），只生成**可核查的上下文块**：

1. 词法检索取前 6；
2. 按问句切出的实体/概念（如“于谦”“北京保卫战”）各取前 10，优先选**以该实体开头的段落**（传记/定义段），补足到 10 条；
3. 词法不足 3 条时才用向量补齐；
4. 每条带 `[S1]` 标号、作品/卷次/篇名、`record_id`、字符区间，提示词要求逐条标注来源、区分记载与推断。

示例（“于谦在北京保卫战中做了什么？”）实际取到 10 条、7,264 字：明通鑑卷 28、皇明經世文編、明史卷 10、明名臣琬琰錄、明英宗睿皇帝實錄、明通鑑卷 22、**明史卷 170（于谦传首段）**、明史紀事本末卷 35、明通鑑卷 30/31。

## 6. 检索评测

**方法**：16 条查询，按“作品 + 卷次”判命中（明實錄等无卷次元数据者只按作品）；取前 10；排除 OCR 记录，避免 OCR 文本与维基文库重复计分。查询覆盖人物（于谦、王振、张居正、郑和、戚继光、王守仁、魏忠贤、海瑞、顾宪成、俺答）、事件（土木、夺门、大礼议、甲申）与制度（漕运、九边）。这是**卷级、单语料、一次运行**的评测，不是统计显著的相关性评估。

| 模式 | recall@10 | MRR |
| --- | ---: | ---: |
| 词法（FTS5） | **1.000** | 0.437 |
| 向量（BGE-small-zh） | 0.688 | **0.458** |
| RRF 混合 | 0.938 | 0.416 |

**解读**：

- 词法对专名、年号、制度词非常稳，16 条全部在前十命中；MRR 不高，说明正确卷不一定排第一（例如“于谦”首条是《明史紀事本末》卷 35，不是卷 170）。
- 向量能补一些词法漏掉的语义相近材料（如“王振”查到《明会要》、“海瑞”查到卷 226），但 top-1 常偏（“于谦”查到《明史紀事本末》卷 16《燕王起兵》，“郑和”查到《明季南略》）。BGE 以现代汉语为主训练，对文言文与明代专名存在明显域差；本次不把它当主检索。
- RRF 在本批下降，原因是两路结果质量不对称；若继续做融合，应改为“词法优先、向量只补位”，或先做查询改写再融合。
- 失败样例：“东林党 顾宪成 无锡 书院”在词法下由《明神宗顯皇帝實錄》命中（不理想但相关），说明卷级命中会掩盖“卷对了、段落不对”的问题；下一轮应做段落级人工标注。

## 7. 质量、缺口与未决

1. **殆知阁的底本与许可**：无 LICENSE、无版本说明、无校对标记；本次只做检索，不据此发布。若要把其中材料用于产品展示，需另找可授权底本或用维基文库/扫描件替代。
2. **明實錄标题缺失**：世宗 308/566、英宗 321/361、太宗 19/130 个“卷之 N”标题；正文长度支持“多数卷仍在、标题被省略”的判断，但没有逐卷核对，不能写成“完整”。
3. **OCR 精度**：三字组召回约 0.46–0.55，且是抄本；只能定位，不能引文。未做 OCR 校对，也未把页号写入分块元数据（页级偏移只在 `pages.jsonl`）。
4. **DOCX 空缺**：没有找到真实、可用的明代 DOCX；解析器只经夹具验证。
5. **旧批次缺失**：本机没有 2026-10-12/18 的 `crawler/` 数据，本次未与旧批次比对，也未复用其简繁视图、分层与 OCR 台账。
6. **未做跨来源互校与版本比对**：维基文库《明史》与殆知阁《明史》未同时入库；《明史 (四庫全書本)》未取；Kanripo《明會典》弘治本未纳入。daizhige 的《大明會典》《明會典》版本关系仍未核。
7. **未接入产品**：没有改 `src/`、API、数据库或前端；按最小方案，v1 不做向量检索。若要把本原型产品化，需另立方案，明确索引存储、权限、许可与评测门槛。
8. **模型训练**：所有材料的 `model_training` 均为 `null`，本次只做检索与推理实验，不训练、不微调。
9. **维基文库未保存修订 ID（revid）**：台账用 URL、`Last-Modified` 与 sha256 定位；页面日后被编辑时，可据散列发现变化，但不能直接回指本次所见修订。
