二、本轮的产品闭环
完成以下一条完整、真实的用户路径：
添加中文史料 → 保存不可变文本版本 → 查看/查找原文 → 选取引文 → 后端从数据库读取指定版本并校验位置与字句 → 保存论断与证据绑定 → 展示多个来源的证据及分歧 → 刷新或重启后仍可回查。

具体能力：
1. 史料管理
   - 支持粘贴中文文本和 UTF-8 .txt 导入，填写标题、来源、版本/整理说明及材料使用条件。
   - 保存作品/材料与不可变文本版本，记录内容散列与创建信息。编辑文本产生新版本，原版本与旧引文继续可回查。
   - 有材料列表、详情、基本查找/筛选和清楚的加载、空数据、失败状态；无需为本轮建立大型采集系统。
2. 引用定位
   - 在原文中选择片段或通过清楚的操作指定位置，前端使用后端约定的 Unicode code point 偏移。
   - 后端按持久版本 ID读取文本，拒绝不存在版本、版本不符、空/越界/反向范围和引文字句不一致。
   - 高亮结果正确处理扩展汉字、重复片段、多行文本与版本变化；不能默默把重复原句定位到错误的出现位置。
   - 原有接受显式文本的定位接口若保留，明确其工具语义；产品主流程必须使用持久化版本，不能用客户端回传原文自校验冒充权威材料查询。
3. 论断与证据工作台
   - 用户可保存简短论断，为其绑定一条或多条引用；证据关系支持“支持、反对、提及、证据不足”及说明。
   - 分别显示论断、来源/版本、引文、关系、人工标注与核查状态。默认未核查；人工标注和位置匹配都不能显示为历史事实已经证实。
   - 支持在同一论断下并列查看不同材料，保留相反记载和未决信息；本轮交付以结构化证据对照为主。
4. 持久性与运行方式
   - 业务数据使用真实 PostgreSQL 和迁移管理，演示环境采用持久数据卷；测试环境使用隔离数据库。
   - 正常刷新、重启后材料、版本、论断和证据不丢失。重复提交/重试不产生重复业务结果，也不能将同文不同出处合并成独立性已确认的单一来源。
   - 提供可重复安装、初始化、演示数据、启动与停止入口。先用本地服务完成交付。

本轮范围聚焦上述闭环。README 的完整知识图谱、自动史实判断、因果解释、地图和大规模采集能力按后续版本维护，不作为本轮已实现能力。无需接入付费外部模型才能完成本轮；fixture 和模拟回应只用于相应测试层，不能冒充真实模型质量。

- API 采用严格输入输出 Schema、稳定错误码、清楚的资源/版本 ID 与必要的分页约定；文档、OpenAPI 和实现同步。
- 前端从固定 OpenAPI快照生成类型，并用运行时 Schema检查回应；共享契约样例同时用于后端和客户端验收。
- React/TypeScript界面优先清楚、易用的中文史料工作台：列表、原文、引文/证据面板和多来源对照。关键动作可从界面完成，不以 Swagger、接口调试器或一页 mock 截图代替产品。
