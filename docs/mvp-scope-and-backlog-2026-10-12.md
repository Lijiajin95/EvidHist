# EvidHist 最小启动需求与待实现清单

日期：2026-10-12（Asia/Shanghai）。状态：**已由用户确认的需求基线；实现与验证尚待后续技术方案**。原创说明采用项目 [CC BY-NC-SA 4.0](../LICENSE-DOCS.md)，第三方材料保留原许可。

本文记录本次 grill 中最后确认的“快速启动”范围。本文所称“首版”，指下一步最小 Agentic 历史研究版本；已有 v0.1「史料与引用工作台」继续复用，实际功能与过去执行过的检查见 [v0.1 交付说明](v0.1-delivery.md)。

此前完整规划中的大量预置资料、三个模型评审、通用代码工具、自动恢复和完整研究界面，已调整为待实现需求。README 的长期功能目录及 [架构分析](architecture-analysis-2026-10-09.md)中的建议，不自动成为首版门槛；发生首版范围冲突时，以本文的最后确认决定为准。本文不修改既有交付记录，也不表示这些能力已经实现。

## 1. 核心目标与范围

EvidHist 帮助研究者形成有证据依据、可复核的历史解释。**首版只服务用户本人，先完成一个真实、可回查的研究任务。**

- 输入：明确的历史问题与一小组人工准备、允许用于该研究流程的真实材料。
- 输出：带来源与引用的初步解释、反证查找结果、争议与未知、一个模型的评审意见，以及可保存的研究报告。
- 使用：复用现有材料与引用工作台，通过简单运行入口开展研究；部署目标为单台 Linux 服务器、私有访问。
- 长期方向：面向重视材料比较与判断复核的研究者，代码计划开源；迁移到现代社会事件分析需要另行验证。商业化不是首版完成条件。
- 试点：明代“于谦—北京保卫战”用于检验产品决策，不作为整个项目的长期年代或题目限制。本轮不展开具体历史结论，实际材料版本及使用条件仍需核查。

研究交付是有范围的初步判断。程序检查通过、模型评审通过和历史事实得到证实，分别处理；资料不足时明确保留缺口，不编造答案。

## 2. 五步工作法怎样应用

采用“质疑需求 → 删除非必要项 → 简化 → 加快反馈 → 自动化”的顺序。方法来源见 [Everyday Astronaut 对 Musk 的采访整理](https://everydayastronaut.com/starbase-tour-and-interview-with-elon-musk/)。下列是本项目的应用决定，不是对来源的逐字引用。

1. **质疑需求**：每项首版要求都说明它怎样帮助完成首次真实研究，或保护结果的可回查性与必要正确性边界。
2. **删除**：拿掉不会阻止首次研究的能力，进入第 6 节待实现清单；不因长期可能有用而保留在首版。
3. **简化**：复用已有数据库、材料接口、引用校验与工作台；采用一个研究 Agent、一个评审模型、一个小业务图和 Pi 薄适配器。
4. **加快反馈**：先完成一个真实任务，修正实际问题，再试另外 1–2 个任务；不等待大资料库、完整界面或评测平台。
5. **自动化**：首版自动化核心研究闭环。资料准备、异常重跑、人工重点复核先由用户处理；新增自动化需要真实使用问题证明价值。

## 3. 首版必须交付的最小闭环

**输入问题 → Pi 研究与反证查找 → 程序校验引用 → 一个模型评审 → 保存报告 → 用户复核关键判断。**

| 编号 | 必须交付 | 最小范围与可检查行为 |
| --- | --- | --- |
| M01 | 任务输入与范围 | 问题清晰时直接执行；影响研究方向的关键歧义先澄清。记录问题与所用材料范围，不增加每次必须批准研究计划的流程。 |
| M02 | 小专题真实资料组 | 人工准备第一任务所需材料，记录来源、版本和允许用途。复用现有文本录入、版本保存与查看能力；不设书目数量或全文量的启动门槛。 |
| M03 | 一个研究 Agent | 在授权材料内检索、比较证据、形成初步解释，并主动查找反证和实际替代解释。记录查找范围与结果；未找到反证不表示反证不存在。 |
| M04 | 引用程序校验 | 复用已有校验，检查文本版本、位置范围和引文匹配。错误不得被模型评分覆盖；可回到保存版本核查。 |
| M05 | 一个模型评审 | 查看报告、引用原文及上下文，保留评语与判定。首版不要求评审模型自主检索整个库，不运行三模型投票；失败或缺评明确记录，不自动视为通过。 |
| M06 | 保存与重点复核 | 保存报告、引用数据及基本日志，按次保留完整版本。用户重点复核核心结论、因果推断和争议点；其他论断不自动变成人工已确认。意见可先写入报告，不新增复核界面。 |
| M07 | 权限与停止边界 | 只开放授权资料的专用只读工具，关闭 Pi 通用 Bash、编辑及文件写入工具。工具范围需要实际检查，不能只依赖工作目录或提示词。保留基本超时和停止能力，失败先人工重跑。 |

基本记录包括实际模型、执行器可提供的 Token 用量、运行时间和必要的工具活动。不可获得的字段明确记为未知；不为首版新建统一计量平台或仪表盘。

## 4. 报告内容与不可删除的正确性边界

报告可采用 Markdown 配合结构化引用数据，具体输出契约由最小技术方案确定。至少能够查看：

- 研究问题、所用材料及研究范围。
- 主要论断、对应引文、来源和保存版本，以及可回查位置。
- 初步解释及依据，原文记载与分析推断的区别。
- 反证查找范围、已有反对材料、替代解释及比较。
- 争议、来源依赖或独立性不明、资料缺口与未知。
- 单模型评审意见、人工重点复核备注和基本运行记录。

原文记载、论断支撑、历史事实判断和因果解释分别表达。现代研究作者的解释与原始材料记载保持区别。支撑程度使用定性表述与理由，不给历史事实虚构数字概率。

原始材料与保存版本保持可回查；处理副本、摘要、模型生成内容不冒充原始材料。使用许可按材料和实际用途核查，遵循 [史料来源与许可指南](source-licensing-guidance.md)。小资料组先人工准备和检查，不建设批量质量审核平台。

模型评审是初期验收依据之一，不能单独证明历史研究质量或用户效果；合成种子、fixture、覆盖率和绿色检查也不能证明真实史料研究有效。

## 5. 技术与启动顺序

保留已选技术方向：**LangGraph 小业务图 → 执行器适配器 → Pi**。首版只实现 EvidHist 当前流程需要的薄适配，不建设通用执行平台、公共包发布体系或复杂插件管理。

复用现有数据库、材料 API、引用校验和材料工作台；不新增研究聊天界面或完整案卷编辑界面。Python 3.14.8、uv 0.12.24、Node 26 基线保持不变。

启动顺序收窄为：

1. 形成最小技术方案，列出接口、允许改动的文件、开发预算及真实验证方式。
2. 完成 LangGraph 与 Pi 的必要接入，提供受限的资料读取能力与基本运行控制。
3. 用一组真实材料跑通一个研究任务，完成程序引用检查、单模型评审与报告保存。
4. 用户实际复核并记录问题，修正后再试另外 1–2 个任务，形成个人可用版本。

扩充通用历史资料库、完成 5–10 个任务覆盖及增加高级能力，放在最小个人版本之后。首次验证不承诺覆盖所有历史问题；任务数用于快速反馈，不构成统计研究质量证明。

每周总投入为 **15 小时**，包括设计、开发、资料、验证、复核与维护。当前接入与实现预算由技术方案另行确定；不能把后续自研 Runtime 的 **20 小时初始验证预算**挪作当前预算。暂无模型调用次数硬上限，运行时间上限及实际可用模型需在方案和试验中明确。
